# Protobuf Network Packet Format

This folder contains the runtime packet codec for frame-sync TCP messages.

## Current Scope

The runtime supports these observer messages:

| Event | Runtime message |
|------|-----------------|
| `PlayerConnect` | `PlayerConnectMessage` |
| `FrameCommand` | `FrameCommandMessage` |
| `SelectHero` | `SelectHeroMessage` |
| `GameStart` | `GameStartMessage` |

`FrameCommand` now carries `tick` plus a repeated authoritative `command_data_list`. Each server tick should broadcast one full frame packet containing one command per connected player. `FrameBatch`, heartbeat, auth, and error messages are not implemented in runtime code. Add them to `BattleObserverEventEnum`, `network_packet_runtime.proto`, and `NetworkProtobufCodec` together if they are needed.

## Repeatable Generation

Run the generator from Unity:

`Tools/Protobuf Converter/Generate Google.Protobuf Sources`

Run it from CI / batchmode:

```powershell
Unity.exe -batchmode -quit -projectPath <project> -executeMethod Rogue.Editor.GoogleProtobufProtocGenerator.GenerateAllForCi
```

It regenerates:

- `Assets/Proto/network_packet_runtime.proto` -> `Assets/Scripts/RunTime/Server/Protobuf/Generated`
- `Assets/Proto/google_protobuf_class_conversion_test.proto` -> `Assets/Scripts/RunTime/TestProtobuf/Generated`

The generator defaults to `E:\protobuf`. CI can override paths with:

- `ROGUE_PROTOBUF_HOME`
- `ROGUE_PROTOC_EXE`
- `ROGUE_PROTOBUF_INCLUDE`

Regenerate the C# message classes with the full Google.Protobuf toolchain:

```powershell
& E:\protobuf\bin\protoc.exe `
  --proto_path=Assets\Proto `
  --proto_path=E:\protobuf\include `
  --csharp_out=Assets\Scripts\RunTime\Server\Protobuf\Generated `
  Assets\Proto\network_packet_runtime.proto
```

## Transport Frame

TCP packets are framed as:

```text
[4-byte little-endian protobuf packet length][NetworkPacket protobuf bytes]
```

`NetworkPacket` contains:

```proto
message NetworkPacket {
    int32 message_type = 1;
    bytes payload = 2;
}
```

The payload is another protobuf message generated from `network_packet_runtime.proto`.

## Runtime Flow

```text
GameEntry.TcpClient.Send(message, eventType)
  -> NetworkProtobufCodec.SerializePacket(eventType, message)
  -> NetworkPacketStreamUtility.WritePacket(stream, packet)

FrameSyncClientComponent.ReceiveData()
  -> NetworkPacketStreamUtility.TryReadPacket(stream, out packet)
  -> NetworkProtobufCodec.TryDeserializePacket(packet, out eventType, out params)
  -> GameEntry.Observer.Notify(eventType, params)

External RogueGameServer
  -> per-client receive buffer
  -> NetworkPacketStreamUtility.TryReadAvailablePacket(...)
  -> server-owned authority frame cache
  -> BroadcastPacket(frame packet)
```

The server uses a per-client receive buffer so a partial TCP packet does not block the server loop.

## Notes

- Protobuf message classes are generated by `E:\protobuf\bin\protoc.exe` into `Generated/NetworkPacketRuntime.cs`.
- `NetworkProtobufCodec` uses `Google.Protobuf` generated classes and only converts between runtime `IObserverParams` objects and generated messages.
- `NetworkPacket.message_type` stores a non-zero wire id: `(int)BattleObserverEventEnum + 1`. This avoids proto3 default-value elision for `PlayerConnect = 0`.
- There is no BinaryReader/BinaryWriter fallback. Both client and server must use this packet format.
- Fixed-point vectors are serialized as integer `fp` component values.
