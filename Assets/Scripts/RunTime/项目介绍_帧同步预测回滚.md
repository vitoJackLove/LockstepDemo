# Roguelike_Master 项目介绍

## 概述

本项目是一款基于 **帧同步（Frame Sync）** 的 Roguelike 游戏框架，核心特色是 **客户端预测 + 权威校验 + 回滚重放** 的联机同步方案。逻辑层使用**定点数（Fixed-Point）**与**固定时间步长**保证多端确定性，支持在延迟与丢包环境下仍能保持流畅的本地操作反馈，并在收到权威结果后自动校正偏差。

---

## 一、帧同步预测回滚架构

### 1.1 三种世界更新类型

逻辑帧内区分三种更新语义，贯穿整条预测–权威–回滚链路：

| 类型 | 说明 |
|------|------|
| **Local** | 本地预测：用本地输入推进一帧，拍摄本地快照，用于后续回滚对比与重放 |
| **Authority** | 权威推进：用服务器下发的该帧指令推进权威世界，拍摄权威快照，并触发预测校验 |
| **RollBack** | 回滚重放：从回滚点开始，用**本地录制的指令**逐帧重放，使本地状态重新追上当前帧 |

所有系统与组件的 `OnFixedUpdate(deltaTime, WorldUpdateType)` 都会根据 `WorldUpdateType` 分支（如仅 Local/RollBack 时执行某些逻辑、Authority 时执行另一些），保证**同一套逻辑**在「预测」「权威」「回滚」三种场景下语义一致且可重放。

### 1.2 主循环与预测流程（BaseWorld）

每固定帧（FixedUpdate）大致流程如下：

1. **本地帧号递增**  
   `_localTick++`，表示当前本地逻辑帧。

2. **获取并记录本帧指令**  
   从 CommandSystem 取本帧玩家输入，写入 `CommandData`（含 Tick、EntityId、MoveDir、SkillDir、CommandType 等），并**录制成「按帧索引的输入序列」**，供回滚时重放。

3. **拍摄本地快照**  
   `TakeLocalSnapShot(_localTick)`：各 System（如 EntitySystem）对**本地实体**按帧号拍摄快照（硬快照 + 软快照），用于之后与权威快照比对。

4. **本地刷新世界（预测）**  
   `LogicUpdateWorld(deltaTime, data)`：  
   - 执行本帧指令 `ExecuteLogicCommand(data)`  
   - 所有系统 `OnFixedUpdate(deltaTime, WorldUpdateType.Local)`  
   即：用**当前帧的本地输入**推进一遍世界，得到「预测状态」。

5. **权威刷新世界（追帧）**  
   `AuthorityUpdateWorld(deltaTime)`：  
   - 当 `_localTick - _authorityTick >= _forecastTick` 时，才推进一帧权威（避免无指令时空跑）。  
   - `_authorityTick++`，从 ServerCommandSystem 取该权威帧的**服务器指令列表**。  
   - **拍摄权威快照** `TakeAuthoritySnapShot(_authorityTick)`。  
   - 用**服务器指令**执行 `ExecuteServerCommand(commandDataList)`，再对所有系统执行 `OnFixedUpdate(deltaTime, WorldUpdateType.Authority)`，得到「权威状态」。  
   - **校验预测** `VerifyForecast(_authorityTick, deltaTime)`：对比该帧的**本地快照**与**权威快照**，若不一致则触发回滚。

整体上，**本地始终领先权威若干帧（_forecastTick）**，实现「边预测边等权威」的体验；一旦发现预测与权威不一致，就回滚到出错帧并用本地录制指令重放，保证最终状态与权威一致。

## 二、回滚机制（RollBack）

### 2.1 回滚触发

在 `VerifyForecast(tick)` 中：

- 对**静态实体**（本地/权威一一对应）：比对该帧的**硬快照**与**软快照**字符串；任一不一致则合并得到 `RollBackType`（软回滚 / 硬回滚）。  
- 对**动态实体**：比对该帧的动态实体快照（数量、指纹、内容），不一致则标记为硬回滚。

若 `rollBackType != NoRollBack`，则调用 `StartRollBack(tick, rollBackType)`。

### 2.2 回滚类型（RollBackType）

- **NoRollBack**：无需回滚。  
- **SoftRollBack**：仅用权威的**软快照**覆盖本地，用于可插值、非关键状态。  
- **HardRollBack**：用权威的**硬快照**覆盖本地，并可能伴随实体创建/销毁（动态实体），保证与权威完全一致。

均为 Flags，可组合（如同时软+硬）。

### 2.3 回滚步骤（StartRollBack）

1. **回滚到出错帧之前**  
   `RollBack(rollBackTick, rollBackType)`：  
   各 System（如 EntitySystem）对该帧执行回滚：静态实体用权威快照做 HardRollBack/SoftRollBack，动态实体按权威快照做创建/销毁/覆盖，使**世界状态回到「出错帧」的权威状态**。

2. **移除错误的本地快照**  
   `RemoveLocalSnapShot(rollBackTick, rollBackType)`：  
   从出错帧到当前本地帧之间的本地快照全部删除，避免后续再被误用。

3. **若为硬回滚：进入「回滚刷新」模式**  
   - `_isStartRollBackUpdate = true`  
   - `_rollBackEndTick = _localTick`（记录回滚要追到的目标帧）  
   - `_localTick = rollBackTick`（本地帧号拉回到回滚点）

之后，在 FixedUpdate 中若 `_isStartRollBackUpdate == true`，不再做「录指令 + 本地预测 + 权威推进」，而是**只做回滚重放**。

### 2.4 回滚重放（RollBackLocalUpdateWorld）

在回滚刷新模式下，每帧调用 `RollBackLocalUpdateWorld(deltaTime)`：

- 用**本地录制的该帧指令** `GetRecodeCommand(_localTick)` 执行 `ExecuteLogicCommand`，再对所有系统执行 `OnFixedUpdate(deltaTime, WorldUpdateType.RollBack)`。  
- 然后 `_localTick++`，直到 `_localTick > _rollBackEndTick`，表示已从回滚点重放回「当前」帧，此时关闭 `_isStartRollBackUpdate`，恢复正常「预测 + 权威」流程。

这样，**同一段输入序列**在回滚后重放，配合确定性逻辑与定点数，会得到与权威一致的状态，从而修正预测错误（如网络延迟、丢包导致的指令不同步）。

## 三、快照与确定性

### 3.1 快照层级

- **按帧存储**：本地快照按 `_localTick`，权威快照按 `_authorityTick`，与「哪一帧的状态」严格对应。  
- **实体级**：每个实体有**硬快照（Hard）**与**软快照（Soft）**；组件/行为树/技能等通过 `TakeSnapShot(hardWriter, softWriter)` 写入，回滚时用 `HardRollBackTo` / `SoftRollBackTo` 从 Reader 还原。  
- **动态实体**：除每实体快照外，还有「该帧动态实体列表（数量 + 指纹）」的快照，用于回滚时比对「该存在哪些、该销毁哪些」，并做创建/销毁/覆盖。

### 3.2 确定性保障

- **固定时间步长**：`LogicDeltaTime` 固定（如 0.033），所有逻辑按 tick 推进，不依赖浮点 deltaTime 累积。  
- **定点数**：位置、方向、速度等使用 `fp`/`fp3` 等定点类型，避免浮点在不同平台/编译器下的差异。  
- **寻路**：`FrameSyncPathfindingSystem` + `FrameSyncPathfinderWrapper` 使用纯逻辑 A* 与定点路径，无随机、无时间戳依赖，同一输入得到同一路径。  
- **指令驱动**：每帧状态仅由「该帧指令 + 上一帧状态」决定，便于录制与重放。

## 四、相关模块一览

| 模块 | 作用 |
|------|------|
| **BaseWorld / BaseWorld.RollBack** | 帧循环、本地/权威/回滚三种更新、快照拍摄、回滚触发与重放 |
| **CommandData / CommandSystem / ServerCommandSystem** | 指令录制、发送、按帧获取权威指令，支持模拟丢包（lossPacket） |
| **EntitySystem.SnapShot / EntitySystem.RollBack** | 实体与动态实体的快照拍摄、移除、硬/软回滚与预测校验 |
| **BaseEntity / BaseComponent** | 实体的 TakeSnapShot、HardRollBackTo、SoftRollBackTo，组件的快照与回滚实现 |
| **PathFindingComponent** | 寻路状态参与快照与硬回滚，保证回滚后路径与权威一致 |
| **BehaviourTree / MoveToPosition 等** | 行为树节点 TakeSnapShot、RollBackTo，与 WorldUpdateType 分支 |
| **WorldUpdateType / RollBackType** | 更新类型与回滚类型枚举，贯穿所有系统与组件 |

---

## 五、总结

本项目通过 **帧同步 + 本地预测 + 权威校验 + 快照回滚重放**，在保证**确定性**与**可重放性**的前提下，实现了：

- **低延迟体验**：本地立即按输入推进，无需等服务器每帧确认。  
- **自动纠错**：权威帧到达后比对快照，一旦不一致则回滚到出错帧并用录制输入重放，使本地与权威重新一致。  
- **可测试性**：可注入丢包率（lossPacket）、预测帧数（forecastTick），验证回滚与重放是否正确。

适合作为 Roguelike、格斗、MOBA 等需要强一致性与手感反馈的联机游戏的底层框架。
